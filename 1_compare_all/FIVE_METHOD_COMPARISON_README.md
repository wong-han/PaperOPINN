# Five-Method Comparison for the Quadrotor Tasks

Run the following scripts directly; no command-line parameters are required:

- `p4_compare_five_quadratic.py`: quadratic-cost quadrotor task.
- `p4_compare_five_nonquadratic.py`: non-quadratic constrained quadrotor task.

The scripts compare LQR, SIREN, MLP, RL, and OPINN. MPC is not included and no
network is trained. By default, each method loads the designated model from its
original training directory rather than selecting the best model from the
multi-seed experiments.

| Method | Quadratic-task model | Non-quadratic-task model |
| --- | --- | --- |
| MLP | `sup_learn_ex_plot/model/mlp_quadrotor3d.pth` | `sup_learn_ex_plot/model/mlp_quadrotor3d_constrained.pth` |
| SIREN | `sup_learn_ex_plot/model/siren_quadrotor3d.pth` | `sup_learn_ex_plot/model/siren_quadrotor3d_constrained.pth` |
| RL | `reinforce_learn_ex_plot/model/rl_quadrotor3d.pth` | `reinforce_learn_ex_plot/model/rl_quadrotor3d_constrained.pth` |
| OPINN | `pihnn_experiments_plot/model/hnn_quadrotor3d_TR_v2_paperplot.pth` | `pihnn_constrained_ex_plot/model/chnn_quadrotor3d_TR_v1.pth` |

Network classes are imported from the corresponding current training programs.
A model must exist and exactly match the expected architecture; otherwise the
script raises an error. Alternative checkpoints, including completed seed
models, can be supplied with `--mlp-model`, `--siren-model`, `--rl-model`, and
`--opinn-model`. The resolved model paths and SHA-256 hashes are stored with the
results.

## Evaluation settings and metrics

- Each task uses 50 Monte Carlo episodes and test seed 2222. An independent
  list of episode seeds is generated first, so all five controllers receive
  the same initial state in each paired episode.
- Initial states are generated by the original environment's `reset` method;
  the sampling range is not modified by the comparison script.
- The environment uses `theoretic_mode=True` and `rl_mode=False`, which
  disables training-specific reward shaping.
- Each episode uses the complete fixed horizon `int(T/dt)`, currently 800
  steps. The `terminated` and `truncated` flags are recorded but do not end a
  finite episode early, matching the earlier comparison convention. A
  non-finite state or cost stops the rollout and marks it as failed.
- An episode is successful when the final position norm is at most 0.1. The
  success rate for each method is printed and saved.
- The cost `J` is the negative cumulative environment return. The constrained
  task retains the constraint penalty defined by the original environment.
- Cost means, standard deviations, and plots use only the successful episodes
  of each method; the sample count may therefore differ among methods.
- The constraint plot retains the earlier metric
  `log10(abs(min_y) + 1e-8)` and also uses successful episodes only. This
  quantity is not a strict constraint-violation depth; the raw `min_y` value is
  saved as well.

## Outputs and plot-only mode

Outputs are written to `results/quadratic_five_methods/` and
`results/nonquadratic_five_methods/`. Existing `data` and `image` directories
from the earlier scripts are not overwritten.

- `data/summary.json`: settings, model provenance, success rates, and metric
  means and standard deviations over successful episodes.
- `data/all_episode_metrics.csv`: metrics and test seeds for every episode.
- `data/all_trajectories_and_metrics.npz`: all states, controls, raw returns,
  and success indicators.
- `data/return_boxplot_data.csv`: `J` values for successful episodes (the
  legacy field name `Return` is retained).
- `data/logy_boxplot_data.csv`: constraint metric for successful constrained
  episodes.
- `image/return_boxplot.*` and `image/min_y_boxplot.*`: violin plots with
  overlaid box and scatter plots, saved as PDF, SVG, and PNG.

The color palette, method order, and 12-by-7-inch layout follow the previous
SIREN comparison. The y-axis label uses `usetex=True` and therefore requires a
local LaTeX installation; other text is rendered by Matplotlib. A method with
no successful episodes is omitted rather than represented by artificial zeros.

After completing a simulation, regenerate the figures without loading models
or rerunning the simulation:

```powershell
python p4_compare_five_quadratic.py --plot-only
python p4_compare_five_nonquadratic.py --plot-only
```

For a quick workflow check, use for example
`--episodes 2 --horizon-steps 20 --device cpu --output-dir <temporary-directory>`.
Results from this shortened horizon must not be used for the formal performance
comparison.
